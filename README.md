# 오늘의 단어

카카오톡 미니게임 "오늘의 단어"를 따라 만든 한글 자모 워들. 원본은 하루 한 판만 할 수 있어서,
친구들과 여러 판 돌려 볼 수 있게 만들었다. 비공식 개인 프로젝트.

링크 하나만 보내면 바로 플레이되는 **자체 완결형 웹 페이지**다. 빌드 결과물 `dist/index.html` 한 파일에
게임과 단어 데이터가 전부 들어 있다. 오늘의 문제·무한 연습·직접 출제는 네트워크 없이도 그대로 동작하고,
Supabase Realtime 설정을 넣어 빌드한 배포본에서만 선택적으로 **같이 하기**가 나타난다.

## 규칙

숨겨진 단어를 다섯 번 안에 맞힌다. 자음과 모음이 **한 칸씩** 들어간다.

쓰는 자모는 24개뿐이다 — `ㄱㄴㄷㄹㅁㅂㅅㅇㅈㅊㅋㅌㅍㅎ` + `ㅏㅑㅓㅕㅗㅛㅜㅠㅡㅣ`.
두벌식 키보드에서 시프트 없이 칠 수 있는 자모와 같고, 나머지는 전부 **두 칸으로 나뉜다**.

| 종류 | 예 |
|---|---|
| 복합모음 | `ㅐ = ㅏ + ㅣ` · `ㅔ = ㅓ + ㅣ` · `ㅘ = ㅗ + ㅏ` · `ㅢ = ㅡ + ㅣ` |
| 쌍자음 | `ㄲ = ㄱ + ㄱ` · `ㅆ = ㅅ + ㅅ` |
| 겹받침 | `ㄳ = ㄱ + ㅅ` · `ㄼ = ㄹ + ㅂ` |

그래서 `시민 → ㅅㅣㅁㅣㄴ` (5칸), `전세 → ㅈㅓㄴㅅㅓㅣ` (6칸), `대응 → ㄷㅏㅣㅇㅡㅇ` (6칸)이 된다.

색은 워들과 같다. 자리까지 맞으면 초록, 단어에는 있지만 자리가 다르면 노랑, 아예 없으면 회색.
같은 자모를 여러 번 썼다면 정답에 들어 있는 개수만큼만 색이 칠해진다(초록 우선, 남는 만큼 왼쪽부터 노랑).

## 모드

- **오늘의 문제** — 날짜(KST) 시드로 정해지므로 같은 날 모두가 같은 문제를 받는다. 칸 수별로 하나씩 있고, 진행 상황은 새로고침해도 남는다.
- **무한 연습** — 원하는 만큼. 최근에 나온 단어는 잘 안 나오게 피한다.
- **직접 출제** — 단어를 정하면 링크가 만들어진다. 카톡으로 보내면 친구가 바로 푼다. 단어는 URL 해시에 base64로 들어가 눈으로는 안 보인다. 주소를 못 쓰는 환경을 위해 링크나 코드를 **붙여넣어서** 시작하는 칸도 있다.
  - **잠금 링크 `#p=<코드>`** (기본값) — 그 문제 하나만 나온다. 처음으로 버튼도 다른 모드도 안 보이고,
    다 풀면 정답과 결과 복사만 뜬다. 맨 아래 `나도 문제 내보기` 글씨 링크 하나로만 전체 게임에 들어갈 수 있다.
  - **일반 링크 `#w=<코드>`** — 출제 화면에서 잠금 체크를 끄면 나온다. 친구가 그 문제를 푼 뒤 전체 게임을 그대로 쓸 수 있다.
  - 붙여넣기로 시작한 문제는 이미 전체 게임 안이라 잠기지 않는다.
- **같이 하기** — 6자리 방 코드나 링크로 모여 방장이 시작하면 모두 같은 단어를 동시에 푼다. 상대 보드에는
  글자 없이 초록·노랑·회색 결과만 보인다. 이 버튼은 빌드할 때 Supabase 설정을 넣은 온라인 배포본에만 나타난다.

4·5·6·7칸을 고를 수 있고, 시도는 어느 칸이든 5번이다. 기록(플레이 수·승률·연승·시도 분포)은 브라우저에만 저장된다.
연승은 오늘의 문제를 이어서 맞힐 때만 올라가고, 친구가 낸 문제는 기록에 넣지 않는다.

## 공유하는 법

1. **GitHub Pages (권장)** — 이 저장소를 GitHub 에 올리고 Settings → Pages 에서 소스를
   `main` 브랜치의 `/docs` 폴더로 지정한다. 몇 분 뒤 `https://<계정>.github.io/<저장소>/` 로 열린다.
   `docs/index.html` 이 그 파일이고, 빌드할 때마다 갱신되므로 다시 커밋만 하면 배포된다.
2. **파일 그대로 보내기** — `dist/index.html` 을 카톡으로 전송. 받은 사람이 열면 바로 실행된다.
3. **직접 열기** — 파일을 더블클릭해도 동작한다.

### 직접 출제 링크가 되는 곳, 안 되는 곳

`직접 출제` 는 주소 뒤에 `#p=` 또는 `#w=` 와 코드를 붙인 링크를 만든다. **주소를 그대로 남에게 보낼 수 있는
환경**(1번 GitHub Pages 같은 진짜 URL)에서만 링크가 나온다.

파일로 열었거나 iframe 안에서 돌고 있으면 — 예를 들어 Claude Artifact 로 게시한 판본은 주소가
`...frame.claudeusercontent.com/_f/...?__frame_t=<일회용 토큰>` 이라 그대로 보내면 받는 쪽에
`page not found` 가 뜬다 — 링크 대신 **문제 코드**를 만들어 준다. 게임 주소와 코드를 함께 보내면
친구가 `직접 출제하기 → 친구가 준 문제 풀기` 칸에 붙여넣어서 풀 수 있다. 그 칸은 코드든 링크
전체든 다 받아들인다.

## 개발

의존성 없음. node 만 있으면 된다.

```
src/index.html   마크업
src/style.css    스타일 (색은 원본 스크린샷에서 추출)
src/hangul.js    자모 분해 · 두벌식 조합 · ASCII 인코딩 · 채점
src/words.js     생성물 — 정답 풀과 검증 사전
src/config.js    멀티플레이 빌드 설정 (저장소에는 빈 값)
src/net.js       Supabase Realtime Broadcast · Presence 어댑터
src/game.js      게임 로직 · 화면 · 저장 · 공유
src/room.js      방 로비 · 참가자 · 실시간 대결 UI

tools/fetch-sources.mjs  원본 단어 데이터 내려받기 (1회)
tools/build-words.mjs    원본 -> src/words.js
tools/build.mjs          src/* -> dist/*.html
tools/test-hangul.mjs    단위 테스트
tools/test-net.mjs       Realtime 프레임 · Presence · 방 규칙 단위 테스트
tools/spike-realtime.mjs 실제 Supabase 프로토콜 왕복 확인
tools/room.mjs           실제 Supabase를 쓰는 다중 브라우저 E2E
tools/shot.mjs           헤드리스 크롬 E2E + 스크린샷
```

```sh
node tools/fetch-sources.mjs    # 처음 한 번만 (data/raw/ 생성, gitignore 됨)
node tools/build-words.mjs      # src/words.js 다시 만들기
node tools/build.mjs            # docs/index.html, dist/index.html, dist/artifact.html

node --test tools/test-hangul.mjs   # 단위 테스트
node --test tools/test-net.mjs      # 멀티플레이 순수 로직 테스트
node tools/shot.mjs                 # 실제 브라우저로 플레이 검증 + dist/shots/*.png
node tools/room.mjs                 # 시크릿 브라우저 2개로 실제 방 대결 검증 (설정 없으면 skip)
```

### 같이 하기 설정

Supabase 프로젝트의 Realtime Broadcast와 Presence를 사용하며 Postgres 테이블은 만들지 않는다. 저장소 루트의
`.env.local`에 아래 값을 넣고 빌드한다. 이 파일은 Git에 포함되지 않는다.

```text
TW_SUPABASE_URL=https://xxxx.supabase.co
TW_SUPABASE_KEY=eyJ...
```

`node tools/spike-realtime.mjs`로 실제 채널 입장·Presence·Broadcast 왕복을 먼저 확인한 뒤
`node tools/build.mjs`를 실행한다. 설정이 없으면 빌드 로그에 멀티플레이가 꺼졌다고 표시되고, 기존 솔로 게임만
담긴 완전한 오프라인 파일이 만들어진다.

`docs/index.html` 이 GitHub Pages 가 서빙하는 파일이라 유일하게 커밋되는 빌드 산출물이다.
`dist/` 는 gitignore 되고, 그 안의 `artifact.html` 은 `<html>`·`<head>`·`<body>` 껍데기가 없는
본문만 담은 판본이다 — 문서 껍데기를 직접 씌우는 호스팅(Claude Artifact 등)에 올릴 때 쓴다.

`tools/shot.mjs` 는 `dist/` 를 로컬 http 서버로 띄운 뒤 헤드리스 크롬으로 접속한다.
`file://` 로 열면 공유 링크와 localStorage 동작이 실제 배포와 달라 검증이 안 되기 때문이다.

### 테스트에 대해

`tools/test-hangul.mjs` 의 채점 케이스는 **카카오톡 원본 스크린샷 6장의 모든 행을 그대로 옮긴 것**이다
(`../today's word/*.jpg`). 정답 `수명·수상·시민·전세·정치·대응` 과 그때 플레이어가 냈던 추측들의
색깔이 한 칸도 틀리지 않고 재현되는지 확인한다. 중복 자모 처리(진실의 `ㅣ`, 대등의 `ㄷ`, 사장의 `ㅏ`)가
특히 중요한 케이스다.

## 단어 데이터

`src/words.js` 는 공개 자료 두 개를 걸러서 만든 파생 목록이다. 원본은 `data/raw/` 에만 두고 커밋하지 않는다.

| 용도 | 출처 | 결과 |
|---|---|---|
| 정답 풀 | 국립국어원 「한국어 학습용 어휘 목록」 ([3beol/3beol.github.io](https://github.com/3beol/3beol.github.io)) | 흔한 2음절 단어 2,443개 (4칸 265 / 5칸 961 / 6칸 1,032 / 7칸 185) |
| 검증 사전 | 표준국어대사전 파생 목록 ([acidsound/korean_wordlist](https://github.com/acidsound/korean_wordlist)) | 자모 4~7칸 단어 106,321개 |

정답은 학습용 어휘 목록에서 2음절만 뽑고 `다`로 끝나는 동사·형용사 기본형은 뺐다.
검증 사전은 표준국어대사전 기반이라 꽤 넓다 — 원본 스크린샷에서 플레이어가 냈던 `효감`, `부돌`,
`매작` 같은 벽지 단어도 그대로 통과한다. 카카오톡 원본도 이 정도로 넓은 사전을 쓰는 것으로 보인다.

용량을 줄이려고 검증 사전은 자모 하나를 `a`~`x` 한 글자로 인코딩해 구분자 없이 이어붙여 두었고,
플레이 중인 칸 수의 집합만 그때그때 펼친다.

두 출처 모두 명시적 라이선스 파일이 없다. 비공식 개인 프로젝트라 그대로 썼으니, 공개 배포할 일이
생기면 우리말샘(CC BY-SA) 같은 라이선스가 분명한 자료로 바꾸는 편이 좋다.

## 원본과 다른 점

- 하루 한 판 제한이 없다 (애초에 이걸 만든 이유)
- 4·7칸이 추가됐다 (원본은 5칸 "오늘의 단어", 6칸 "오늘의 챌린지")
- 직접 출제, 결과 이모지 복사, 기록 통계가 있다
